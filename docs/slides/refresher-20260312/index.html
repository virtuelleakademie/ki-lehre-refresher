LLMs als Textvorhersage

Ein Sprachmodell sagt das nächste Wort vorher, basierend auf allem, was davor steht.


\[P(\text{Wort}_{i+1} \mid \text{Kontext}, \text{Modell})\]


Gegeben “Der Hund liegt auf dem”, berechnet das Modell:

  • “Boden” → 32%
  • “Sofa” → 24%
  • “Bett” → 18%
  • “Teppich” → 14%
  • …

Das Modell wählt ein Wort, hängt es an den Kontext an, und wiederholt den Prozess. So entsteht Text, Wort für Wort.


Zwei Faktoren bestimmen die Vorhersage:

  1. Kontext: Was wurde bisher gesagt?
  2. Modell: Was hat das System aus Trainingsdaten gelernt?


Für eine vertiefte Einführung: BFH Beginner-Kurs

Ein Sprachmodell wie ChatGPT funktioniert im Kern wie ein ausgefeilter Autocomplete-Mechanismus. Es sagt das nächste Wort vorher, basierend auf dem bisherigen Kontext und dem, was es aus Trainingsdaten gelernt hat. Dieser Prozess wiederholt sich Wort für Wort. Für eine vertiefte Einführung verweise ich auf den Beginner-Kurs. Was für unsere heutige Diskussion zählt, ist eine bestimmte Eigenschaft dieses Prozesses.

Die entscheidende Eigenschaft



LLMs produzieren Text, der flüssig, selbstbewusst und kohärent klingt.


Das Ergebnis liest sich wie ein Expertentext.

Aber Flüssigkeit ist nicht dasselbe wie Korrektheit.


Warum das für Lernen gefährlich ist, erklärt die Cognitive Load Theory.

Das Arbeitsgedächtnis als Nadelöhr

Alles Lernen muss durch einen Engpass: das Arbeitsgedächtnis.


Eigenschaft
Kapazität ~4 Elemente
Dauer 15-30 Sekunden
Verarbeitung 1 Element aktiv


Keine Technologie kann diesen Engpass umgehen. KI kann Information liefern, aber die aktive Verarbeitung muss im eigenen Kopf stattfinden.

  const slider = div.querySelector("input[type=range]");
  const label = div.querySelector("strong");
  const resetBtn = div.querySelector("button");

  function emit() {
    div.value = +slider.value;
    div.dispatchEvent(new Event("input", { bubbles: true }));

    label.textContent = slider.value + "%";
    emit();

  resetBtn.onclick = () => {

    label.textContent = "10%";
    emit();
  };

  div.value = 60;
  return div;

  const w = 420;
  const h = 320;

    "Lernrelevante Verarbeitung": "#0072B2",

    {type: "Lernrelevante Verarbeitung", value: learning, order: 2},

Das Arbeitsgedächtnis ist der Flaschenhals, durch den alles Lernen hindurch muss. Es kann ungefähr vier Elemente gleichzeitig halten, und zwar für 15 bis 30 Sekunden. Bewegt den Slider: Bei hoher extrinsischer Belastung bleibt kaum Kapazität für lernrelevante Verarbeitung. Klickt auf “Gutes Lerndesign”: Extrinsische Last auf 10%, und sofort wird Kapazität frei.

Expertise = vernetzte Schemata

Wie überwindet man den Engpass? Durch Schemata: mentale Strukturen, die viele Einzelelemente zu einer Einheit komprimieren.

novice_expert_schemas = {
  const w = schemas_width;
  const h = schemas_height;
  const fs = schemas_font_size;

  const colNeg = "#D55E00";
  const colPos = "#0072B2";
  const colNeutral = "#64748b";
  const colCross = "#B8821A";

  const labels = [
    "Fakt A", "Fakt B", "Fakt C",
    "Regel 1", "Regel 2", "Regel 3",
    "Def. X", "Def. Y", "Def. Z"
  ];
  const clusters = [0, 0, 0, 1, 1, 1, 2, 2, 2];

  const novicePos = [
    [0.12, 0.22], [0.38, 0.12], [0.65, 0.20],
    [0.18, 0.50], [0.45, 0.48], [0.72, 0.55],
    [0.08, 0.80], [0.42, 0.82], [0.70, 0.78]
  ];

  const expertPos = [
    [0.15, 0.22], [0.30, 0.22], [0.225, 0.40],
    [0.60, 0.22], [0.75, 0.22], [0.675, 0.40],
    [0.33, 0.72], [0.48, 0.72], [0.405, 0.88]
  ];

  const intraEdges = [
    [0, 1], [1, 2], [0, 2],
    [3, 4], [4, 5], [3, 5],
    [6, 7], [7, 8], [6, 8]
  ];

  const crossEdges = [[1, 3], [2, 6], [5, 7]];

  const clusterBoxes = [
    { x: 0.08, y: 0.12, w: 0.30, h: 0.38, label: "Schema 1" },
    { x: 0.53, y: 0.12, w: 0.30, h: 0.38, label: "Schema 2" },
    { x: 0.26, y: 0.62, w: 0.30, h: 0.36, label: "Schema 3" }
  ];

  const mx = 40, my = 30;
  const cw = w - 2 * mx;
  const ch = h - 2 * my;
  const toX = (nx) => mx + nx * cw;
  const toY = (ny) => my + ny * ch;

  const svg = d3.create("svg")
    .attr("width", w).attr("height", h)
    .attr("viewBox", `0 0 ${w} ${h}`)
    .style("background", "transparent")
    .style("cursor", "pointer")
    .style("user-select", "none");

  const clusterGs = svg.selectAll("g.cluster-bg")
    .data(clusterBoxes).join("g").attr("class", "cluster-bg");

  clusterGs.append("rect")
    .attr("x", d => toX(d.x)).attr("y", d => toY(d.y))
    .attr("width", d => d.w * cw).attr("height", d => d.h * ch)
    .attr("rx", 4).attr("fill", colPos).attr("fill-opacity", 0)
    .attr("stroke", colPos).attr("stroke-opacity", 0)
    .attr("stroke-width", 1.5).attr("stroke-dasharray", "6,4");

  clusterGs.append("text")
    .attr("x", d => toX(d.x + d.w / 2)).attr("y", d => toY(d.y) - 6)
    .attr("text-anchor", "middle").style("font-size", "12px")
    .style("fill", colPos).style("font-style", "italic").style("opacity", 0)
    .text(d => d.label);

  const intraLines = svg.selectAll("line.intra")
    .data(intraEdges).join("line").attr("class", "intra")
    .attr("x1", d => toX(novicePos[d[0]][0])).attr("y1", d => toY(novicePos[d[0]][1]))
    .attr("x2", d => toX(novicePos[d[1]][0])).attr("y2", d => toY(novicePos[d[1]][1]))
    .attr("stroke", colPos).attr("stroke-width", 2).attr("stroke-opacity", 0);

  const crossLines = svg.selectAll("line.cross")
    .data(crossEdges).join("line").attr("class", "cross")
    .attr("x1", d => toX(novicePos[d[0]][0])).attr("y1", d => toY(novicePos[d[0]][1]))
    .attr("x2", d => toX(novicePos[d[1]][0])).attr("y2", d => toY(novicePos[d[1]][1]))
    .attr("stroke", colCross).attr("stroke-width", 1.5).attr("stroke-opacity", 0)
    .attr("stroke-dasharray", "4,3");

  const nodeR = 28;
  const nodeGs = svg.selectAll("g.node")
    .data(labels.map((l, i) => ({ label: l, i })))
    .join("g").attr("class", "node")
    .attr("transform", d => `translate(${toX(novicePos[d.i][0])},${toY(novicePos[d.i][1])})`);

  nodeGs.append("rect")
    .attr("x", -nodeR).attr("y", -14).attr("width", nodeR * 2).attr("height", 28)
    .attr("rx", 4).attr("fill", colNeg).attr("fill-opacity", 0.8);

  nodeGs.append("text")
    .attr("text-anchor", "middle").attr("dy", "0.35em")
    .style("font-size", "12px").style("font-weight", "bold").style("fill", "white")
    .text(d => d.label);

  const subtitle = svg.append("text")
    .attr("x", w / 2).attr("y", h - 8)
    .attr("text-anchor", "middle").style("font-size", fs).style("fill", colNeutral)
    .text("Isolierte Fakten \u2014 klicken zum Vernetzen");

  let expert = false;

  svg.on("click", () => {
    expert = !expert;
    const dur = 1000;
    const ease = d3.easeCubicInOut;

    nodeGs.transition().duration(dur).ease(ease)
      .attr("transform", d => {
        const pos = expert ? expertPos[d.i] : novicePos[d.i];
        return `translate(${toX(pos[0])},${toY(pos[1])})`;
      });

    nodeGs.select("rect").transition().duration(dur).ease(ease)
      .attr("fill", expert ? colPos : colNeg);

    intraLines.transition().duration(dur).ease(ease)
      .attr("x1", d => toX((expert ? expertPos : novicePos)[d[0]][0]))
      .attr("y1", d => toY((expert ? expertPos : novicePos)[d[0]][1]))
      .attr("x2", d => toX((expert ? expertPos : novicePos)[d[1]][0]))
      .attr("y2", d => toY((expert ? expertPos : novicePos)[d[1]][1]))
      .attr("stroke-opacity", expert ? 0.6 : 0);

    crossLines.transition().duration(dur).ease(ease)
      .attr("x1", d => toX((expert ? expertPos : novicePos)[d[0]][0]))
      .attr("y1", d => toY((expert ? expertPos : novicePos)[d[0]][1]))
      .attr("x2", d => toX((expert ? expertPos : novicePos)[d[1]][0]))
      .attr("y2", d => toY((expert ? expertPos : novicePos)[d[1]][1]))
      .attr("stroke-opacity", expert ? 0.4 : 0);

    clusterGs.select("rect").transition().duration(dur).ease(ease)
      .attr("fill-opacity", expert ? 0.06 : 0)
      .attr("stroke-opacity", expert ? 0.5 : 0);

    clusterGs.select("text").transition().duration(dur).ease(ease)
      .style("opacity", expert ? 1 : 0);

    subtitle.transition().duration(300).style("opacity", 0)
      .transition().delay(expert ? 600 : 0).duration(300).style("opacity", 1)
      .text(expert
        ? "Vernetzte Schemata \u2014 klicken zum Aufl\u00f6sen"
        : "Isolierte Fakten \u2014 klicken zum Vernetzen");
  });

  return svg.node();
}

Wie überwindet man den Engpass? Durch Schemata. Ein Schema komprimiert viele Einzelelemente zu einer Einheit und belegt nur einen Slot im Arbeitsgedächtnis. Klickt auf die Grafik: Links seht ihr isolierte Fakten, wie sie Anfänger:innen im Arbeitsgedächtnis halten müssen. Nach dem Klick: vernetzte Schemata, wie sie Expert:innen haben. Die Progression von isolierten Fakten zu vernetzten Schemata erfordert eigene kognitive Arbeit.

Extrinsische Last: der Split-Attention-Effekt

Wenn Lernende zwischen zwei Informationsquellen hin- und herspringen müssen, entsteht unnötige kognitive Belastung.

    svg.append("line").attr("x1", arrowX1).attr("y1", arrowY - 6).attr("x2", arrowX2).attr("y2", arrowY - 6).attr("stroke", "#D55E00").attr("stroke-width", 1.5).attr("stroke-dasharray", "5,4").attr("marker-end", "url(#arrowhead-split)");

    svg.append("text").attr("x", (arrowX1 + arrowX2) / 2).attr("y", arrowY - 16).attr("text-anchor", "middle").attr("font-size", fsSmall - 1).attr("fill", "#D55E00").attr("font-weight", "600").text("Blickbewegung");
  }

}

Wechselt zwischen den Formaten. Integriertes Design eliminiert die unnötige kognitive Belastung.

Der Split-Attention-Effekt ist ein klassisches Beispiel für extrinsische Last. Links das Split-Format: Die Lernenden müssen zwischen Dreieck und Lösungsschritten hin- und herspringen. Jede Blickbewegung kostet Arbeitsgedächtnis. Rechts das integrierte Format: Alles an einem Ort. Dieselbe Information, aber weniger extrinsische Last. Wechselt zwischen den Formaten, um den Unterschied zu sehen.

Vorwissen bestimmt das Aufgabendesign

Dieselbe Aufgabe hat unterschiedliche intrinsische Last für verschiedene Lernende.


Aufgabe: Löse \(-1(-x - 7) = 2x - 20\)


Für Anfänger:innen

Hohe Elementinteraktivität:

  • Was bedeutet das Minuszeichen vor der Klammer?
  • Wie verteile ich?
  • Wie bringe ich \(x\) auf eine Seite?
  • Welche Rechenregeln gelten?

Jedes Element muss einzeln im Arbeitsgedächtnis gehalten werden.



Für Fortgeschrittene

Niedrige Elementinteraktivität:

  • “Klammer auflösen” → ein Schema
  • “Terme zusammenfassen” → ein Schema
  • “Nach \(x\) auflösen” → ein Schema

Drei Schritte, drei Slots. Problemlos.


→ Dieselbe Aufgabe, aber verschiedene kognitive Kosten.

Hier wird es für das Aufgabendesign entscheidend. Dieselbe Gleichung hat völlig unterschiedliche kognitive Kosten für verschiedene Lernende. Für Anfänger:innen ist jedes Element einzeln zu verarbeiten. Für Fortgeschrittene sind das drei automatisierte Schritte. Dieselbe Aufgabe, aber radikal verschiedene Anforderungen ans Arbeitsgedächtnis.

Was für Anfänger:innen hilft, schadet Fortgeschrittenen, und umgekehrt.

Die Aufgabe muss zum Vorwissen passen, nicht umgekehrt.

Der Expertise-Umkehr-Effekt. Bewegt den Slider: Bei Anfängern sind Worked Examples klar überlegen. Bei Experten kehrt sich das um, Worked Examples werden redundant und stören. Am Umschlagpunkt sind beide Methoden gleich effektiv. Die Konsequenz: Ein Übungsblatt für alle ist per Definition für die meisten falsch.

Scaffolding steuert die intrinsische Last

Wenn die intrinsische Last zu hoch ist, brauchen Lernende Gerüste, nicht einfach mehr Zeit.


Vom Beispiel zum Problem (Fading)

Schritt Format
1 Worked Example: Vollständig durchgearbeitet
2 Completion Problem: Teilweise gelöst, Lücken füllen
3 Hinweis-gestützt: Nur strategische Hinweise
4 Eigenständig: Ohne Unterstützung


Jede Stufe reduziert die Unterstützung und erhöht die kognitive Eigenleistung.

Beispiel: Gleichung lösen

Stufe 1 (Worked Example):

\(-1(-x - 7) = 2x - 20\)

Schritt 1: Klammer auflösen → \(x + 7 = 2x - 20\)

Schritt 2: \(x\) isolieren → \(7 + 20 = 2x - x\)

Schritt 3: Vereinfachen → \(27 = x\)


Stufe 2 (Completion):

\(-1(-x - 7) = 2x - 20\)

Schritt 1: Klammer auflösen → \(\underline{\quad\quad\quad\quad}\)

Schritt 2: \(x\) isolieren → \(7 + 20 = 2x - x\)

Schritt 3: Vereinfachen → \(27 = x\)

Scaffolding ist das dritte Prinzip. Die effektivste Strategie ist Fading: Man beginnt mit vollständig durchgearbeiteten Beispielen, geht dann zu Completion Problems über, dann zu Hinweisen, und schliesslich zu eigenständigem Lösen. Bei unserem Gleichungsbeispiel: Stufe 1 zeigt die vollständige Lösung, Stufe 2 lässt den ersten Schritt offen.

Was passiert, wenn Studierende ChatGPT benutzen?

ChatGPT liefert die Lösung. Aber nicht das Scaffolding.


ChatGPT-Antwort

“Löse \(-1(-x - 7) = 2x - 20\)”

→ Sofort die vollständige Lösung, korrekt formatiert, flüssig formuliert.

  • Keine Diagnose des Vorwissens
  • Keine angepasste Unterstützung
  • Keine Lücken zum Selbstdenken
  • Kein Fading

Das Produkt sieht aus wie ein Worked Example, ist aber keines.

Der Unterschied

Ein Worked Example ist pädagogisch gestaltet:

  • Schritte sind so gewählt, dass Schemata aufgebaut werden
  • Die Struktur lädt zur Selbsterklärung ein
  • Es ist Teil einer Fading-Sequenz

ChatGPT-Output ist optimiert für Korrektheit und Flüssigkeit, nicht für Schemabildung.

Wer die Lösung liest, ohne selbst zu verarbeiten, baut keine Schemata auf.

Hier treffen die LLM-Eigenschaft und die CLT-Prinzipien aufeinander. ChatGPT-Output sieht aus wie ein Worked Example, ist aber keines. Ein echtes Worked Example ist pädagogisch gestaltet und Teil einer Fading-Sequenz. ChatGPT-Output ist für Korrektheit und Flüssigkeit optimiert, nicht für Schemabildung. Und weil der Output flüssig ist, entsteht die Illusion des Verstehens.

Das Evaluationsparadox



Um KI-Output zu beurteilen,

braucht man die Schemata,

die die Aufgabe aufbauen sollte.


Ohne eigene Schemata gibt es kein internes Referenzsignal.

Flüssiger KI-Output unterdrückt den Zweifel.

Das ist keine Frage der Motivation. Das ist kognitive Architektur.

Das Evaluationsparadox schliesst den Kreis. Um zu beurteilen, ob ein KI-Output korrekt ist, braucht man genau die Schemata, die die Aufgabe aufbauen sollte. Das ist keine Frage der Motivation. Das ist kognitive Architektur.

Die Designfrage



Wenn unstrukturierte ChatGPT-Nutzung das Problem ist:


Wie sähe ein KI-Tool aus, das CLT-Prinzipien umsetzt?


Antwort: Ein Tool, das zuerst diagnostiziert und dann angepasst scaffoldet.

Wenn unstrukturierte ChatGPT-Nutzung das Problem ist, wie sähe ein KI-Tool aus, das CLT-Prinzipien umsetzt? Ein Tool, das zuerst diagnostiziert, wo die Lernenden stehen, und dann die Unterstützung anpasst.

Beispiel: Gleichungen lösen

Aufgabe: \(-1(-x - 7) = 2x - 20\)

Diese Aufgabe erfordert drei Teilkompetenzen:


Schritt 1

Distribuieren

\(-1 \cdot (-x) = x\)

\(-1 \cdot (-7) = 7\)

→ \(x + 7 = 2x - 20\)

Schritt 2

Terme zusammenfassen

\(7 + 20 = 2x - x\)

→ \(27 = x\)

Schritt 3

Variable isolieren

\(x = 27\)

Prüfung: \(-1(-27-7) = 2(27)-20\)

\(34 = 34\)


Ein CLT-informiertes Tool fragt: Welche dieser Teilkompetenzen beherrscht die Person bereits?

Die Gleichung erfordert drei Teilkompetenzen: Distribuieren, Terme zusammenfassen, Variable isolieren. Ein CLT-informiertes Tool diagnostiziert zuerst: Welche dieser Teilkompetenzen beherrscht die Person bereits? Je nach Antwort wird unterschiedlich scaffoldet.

ChatGPT vs. CLT-Tool

ChatGPT (unstrukturiert)

“Löse \(-1(-x - 7) = 2x - 20\)”

→ Sofort vollständige Lösung

  • Keine Diagnose
  • Kein Fading
  • Keine Lücken
  • Flüssiger Output erzeugt Kompetenz-Illusion

Wer denkt? Die Maschine.

Ergebnis: Produkt ohne Schemabildung.

CLT-informiertes Tool

“Löse \(-1(-x - 7) = 2x - 20\)”

→ Erst Diagnose, dann angepasstes Scaffolding

  • Diagnostiziert Vorwissen
  • Passt Unterstützung an
  • Lässt Lücken zum Selbstdenken
  • Baut Scaffolding schrittweise ab

Wer denkt? Die Lernenden, mit Unterstützung.

Ergebnis: Schemabildung durch eigene Verarbeitung.


Dasselbe Material. Dieselbe Technologie. Anderes Design. Anderes Lernergebnis.

Der direkte Vergleich. ChatGPT: Die Maschine denkt, keine Schemata. CLT-Tool: Die Lernenden denken, mit Unterstützung. Dasselbe Material, dieselbe Technologie, aber anderes Design und damit ein anderes Lernergebnis.

Drei Erkenntnisse


1. Extrinsische Last minimieren ist der einfachste Hebel. Klare Aufgaben, konsistente Notation, integriertes Format.


2. Vorwissen bestimmt das Aufgabendesign. Ein Übungsblatt für alle ist für die meisten falsch. Diagnostik ist der Schlüssel.


3. KI kann CLT-Prinzipien umsetzen, aber nur wenn sie dafür gebaut wird. ChatGPT ist kein Lerntool. Ein CLT-informiertes Tool kann eines sein.

Drei Erkenntnisse zum Mitnehmen. Erstens: Extrinsische Last minimieren kostet nichts. Zweitens: Vorwissen bestimmt, wie die Aufgabe aussehen muss. Drittens: KI kann CLT-Prinzipien umsetzen, aber nur wenn sie dafür designt wird.

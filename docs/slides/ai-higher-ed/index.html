Das Paradox



Aufgabenleistung ≠ Lernen

  • Magenta = KI-Gruppe, Grau = Kontrollgruppe
  • Übungsphase: KI-Gruppe klar besser (keine Überlappung der Fehlerbalken)
  • Test: KI-Gruppe schlechter, aber Fehlerbalken überlappen
  • Kernaussage: Aufgabenleistung ≠ Lernen
  • Mit KI-Hilfe sehen wir Systemperformanz, nicht Lernen

Das Nadelöhr des Lernens

Kernaussage: Alles Lernen muss durch das Nadelöhr des Arbeitsgedächtnisses (Sweller 2024).

  • Vereinfachtes Gedächtnismodell: Neue Info → Arbeitsgedächtnis → Langzeitgedächtnis
  • Arbeitsgedächtnis: nur 4±1 Elemente gleichzeitig
  • Neue Info und Langzeitgedächtnis: unbegrenzt
  • Cognitive Load Theory: Alles Lernen muss durch dieses Nadelöhr
  • Keine Abkürzung, keine KI kann biologischen Engpass umgehen

Erwünschte Schwierigkeiten



“Conditions that slow the rate of apparent learning often optimize long-term retention and transfer.”


Robert Bjork (Bjork und Bjork 2011)



Schwerer fühlt sich schlechter an, ist aber besser für langfristiges Lernen.

  • “Desirable Difficulties” (erwünschte Schwierigkeiten)
  • Bjork: Bedingungen, die Lernen verlangsamen, optimieren langfristiges Behalten
  • Schwerer fühlt sich schlechter an, ist aber besser fürs Lernen
  • Wenn Lernen sich leicht anfühlt, lernen wir wahrscheinlich weniger

Die vier Strategien



Selbst generieren

Eigene Antworten formulieren


Verteilt lernen

Zeitliche Abstände einbauen


Aktiv abrufen

Wissen aus dem Gedächtnis holen


Variieren

Themen und Aufgaben mischen



KI kann jede dieser Strategien untergraben, wenn sie die kognitive Arbeit übernimmt.

  • Vier Strategien nach Bjork:
    1. Selbst generieren (eigene Antworten)
    2. Verteilt lernen (zeitliche Abstände)
    3. Aktiv abrufen (aus Gedächtnis holen)
    4. Variieren (Themen/Aufgaben mischen)
  • KI kann alle vier untergraben, wenn sie kognitive Arbeit übernimmt

Der Generierungseffekt

Selbst generierte Information wird besser behalten (Slamecka und Graf 1978).


Wenn KI generiert, was Studierende selbst produzieren sollten, entfällt der Lerneffekt.

  • Behaltensleistung: Selbst generiert (~70%) > Gelesen (~50%) > Von KI (~35%)
  • Forschung seit 1970er (Slamecka & Graf)
  • Wenn KI generiert statt Studierende → Lerneffekt entfällt

Offloading vs. Outsourcing

  • Offloading: Werkzeug reduziert Arbeitsgedächtnislast, du denkst weiter
  • Outsourcing: Werkzeug ersetzt dein Denken
  • Nicht jede KI-Nutzung ist gleich: Spektrum von hilfreich bis schädlich
  • Beispiele zeigen den graduellen Übergang
  • Die entscheidende Frage: Bleibt die lernrelevante Verarbeitung beim Lernenden?

Historische Analogien


Das Muster wiederholt sich. Aber: KI ist breiter als GPS oder Taschenrechner.

(Dahmani und Bohbot 2020; Sparrow, Liu, und Wegner 2011)

  • 1970er Taschenrechner: konzeptuelles Mathe-Verständnis ↓
  • 1990er GPS: räumliches Gedächtnis ↓
  • 2000er Google: “Wo” ersetzt “Was”
  • 2020er KI: kombiniert und verstärkt alle Effekte
  • Unterschied: KI betrifft alle kognitiven Domänen, nicht nur eine

Experten vs. Lernende


Experten:


  • Können Routine auslagern
  • Können KI-Output bewerten
  • Mehr Kapazität für Komplexes

Lernende:


  • Können nicht bewerten
  • Überspringen Grundlagen
  • Risiko: “Fliessende Inkompetenz”


Dasselbe Werkzeug, fundamental unterschiedliche Auswirkungen.

  • Experten: können Routine auslagern, Output bewerten, Kapazität für Komplexes
  • Lernende: können Output nicht bewerten, überspringen Grundlagen
  • Risiko: “fliessende Inkompetenz” (mit Hilfe alles, ohne Hilfe nichts)
  • Fazit: Dasselbe Werkzeug, fundamental unterschiedliche Auswirkungen

config = ({
  // Color palette
  colors: {

    neutral: "#333",
    background: "#f5f5f5"
  },
  // Line equations: y = intercept + slope * x
  lines: {
    high: { intercept: 65, slope: -0.4 },
    low: { intercept: 25, slope: 0.4 }
  },
  // Input options
  steps: [0, 20, 40, 60, 80, 100],
  defaultValue: 20,
  // Plot dimensions
  plot: {
    width: 900,
    height: 480,
    margins: { left: 70, bottom: 60, top: 30, right: 40 }
  },
  // Labels
  labels: {
    highSupport: "Hohe Unterstützung",
    lowSupport: "Niedrige Unterstützung",
    highExamples: ["📖 Worked Examples", "🧭 Direkte Instruktion"],
    lowExamples: ["🧩 Problembasiertes Lernen", "🔍 Eigene Lösungswege"]
  }

crossoverPoint = {
  const { high, low } = config.lines;
  return (high.intercept - low.intercept) / (low.slope - high.slope);
}

calcY = (line, x) => line.intercept + line.slope * x

viewof vorwissen = {
  const input = Inputs.radio(config.steps, {
    value: config.defaultValue,
    label: "",
    format: x => x + "%"
  });
  input.style.display = "none";
  return input;
}

currentState = {
  const x = vorwissen ?? config.defaultValue;
  const highY = calcY(config.lines.high, x);
  const lowY = calcY(config.lines.low, x);
  const isHighBetter = x <= crossoverPoint;

  return {
    x,
    highY,
    lowY,
    isHighBetter,
    optimalY: isHighBetter ? highY : lowY,
    suboptimalY: isHighBetter ? lowY : highY,
    optimalLabel: isHighBetter ? config.labels.highSupport : config.labels.lowSupport,
    optimalColor: isHighBetter ? config.colors.highSupport : config.colors.lowSupport,
    suboptimalColor: isHighBetter ? config.colors.lowSupport : config.colors.highSupport
  };
}

Das Evaluationsparadox


Um KI-Output kritisch zu bewerten, braucht man die Kompetenz, die erst durch Lernen entsteht.



Für Experten:

Bewertung möglich, weil Wissen vorhanden

Für Lernende:

Bewertung unmöglich, weil Wissen erst aufgebaut wird


Das ist die zentrale Spannung beim KI-Einsatz in der Lehre.

  • Das Evaluationsparadox: Um KI-Output zu bewerten, braucht man Kompetenz
  • Experten können bewerten, weil Wissen vorhanden
  • Lernende können nicht bewerten, weil Wissen erst aufgebaut wird
  • Das ist die zentrale Spannung beim KI-Einsatz in der Lehre

Vier kognitive Operationen



Abrufen

Wissen aus dem Gedächtnis aktivieren


Generieren

Eigene Lösungen produzieren


Verknüpfen

Elemente vergleichen und integrieren


Überwachen

Gegen interne Kriterien bewerten



Diese Operationen bauen Schemata auf. KI kann jede einzelne ersetzen.

  • Vier kognitive Operationen, die Schemata aufbauen:
    1. Abrufen: Wissen aus dem Gedächtnis aktivieren
    2. Generieren: Eigene Lösungen produzieren
    3. Verknüpfen: Elemente vergleichen und integrieren
    4. Überwachen: Gegen interne Kriterien bewerten
  • KI kann jede dieser Operationen ersetzen
  • Wenn die KI abruft, generiert, verknüpft und überwacht, lernt der Mensch nicht

Das Paradox visualisiert

  • Zyklus: KI-Output bewerten → erfordert Fachkompetenz → entsteht durch Lernen → erfordert eigenes Denken → wird ersetzt durch KI
  • Der Kreislauf schliesst sich: KI ersetzt genau das Denken, das zum Lernen nötig wäre
  • Gestrichelte Linie zeigt den problematischen Bruch

Was das für die Lehre bedeutet


Studierende müssen interne Modelle aufbauen, bevor sie KI kritisch nutzen können.


“Critical thinking is not a skill. There is not a set of critical thinking skills that can be acquired and deployed regardless of context.”

Daniel Willingham (Willingham 2008)


Die vier Operationen (Abrufen, Generieren, Verknüpfen, Überwachen) müssen im Kopf der Lernenden stattfinden, nicht in der KI.

  • Studierende brauchen interne Modelle BEVOR sie KI kritisch nutzen können
  • Willingham: Kritisches Denken ist keine kontextfreie Fähigkeit
  • Die vier kognitiven Operationen müssen im Kopf der Lernenden stattfinden
  • Keine Abkürzung: erst das Fundament, dann das Werkzeug




Aber warum lagern Studierende überhaupt aus?



Sind sie faul? Unehrlich? Oder… rational?

  • Übergang zur Bounded Rationality
  • Warum lagern Studierende kognitive Arbeit an KI aus?
  • Naheliegende Erklärungen: Faulheit, Unehrlichkeit
  • Alternative Erklärung: rationales Verhalten in einer bestimmten Umgebung

Ein Gespräch an der BFH

Ein Mathematik-Dozent berichtet:

“Wir nutzen lokale KI-Modelle für Prüfungserstellung und Korrektur. Aber bei Studierenden sehen wir: Sie kommen nicht zu Übungsstunden, stellen keine Fragen, üben nicht. Ihnen fehlt die intrinsische Motivation.”


Die Diagnose:

Motivationsproblem

KI-Lösung: Gamifizierte KI-Übungen, KI-Tutoren die “engagieren”

Das eigentliche Problem:

Cognitive Overload

Die Aufgaben überlasten das Arbeitsgedächtnis, weil die nötigen Schemata fehlen.


Falsche Diagnose führt zu falscher KI-Intervention. Nicht die Ameise ist das Problem, sondern der Strand.

  • Reales Gespräch mit BFH-Mathematik-Dozent (anonymisiert)
  • Der Dozent ist selbst KI-Praktiker: lokale Modelle für Prüfungen, Korrekturen, vertrauliche Dokumente
  • Er repräsentiert genau das Publikum dieser Präsentation
  • Seine Diagnose: Studierende haben keine intrinsische Motivation zum Üben
  • Reframing: Die Studierenden sind nicht unmotiviert, sie sind überfordert
  • Wenn Arbeitsgedächtnis überlastet ist (fehlende Schemata), fühlt sich jede Aufgabe unmöglich an
  • Das sieht aus wie Motivationsmangel, ist aber kognitive Überlastung
  • Falsche Diagnose führt zu falscher KI-Intervention:
    • “Motivation” → Gamification, KI-Engagement-Tools → behandelt Symptom
    • “Cognitive Load” → Scaffolded Übungen, besseres Aufgabendesign → behandelt Ursache
  • Der richtige KI-Einsatz: KI für den DOZENTEN zum Redesign der Aufgaben
    • Schwierigkeit kalibrieren, gestufte Übungen erstellen
    • Nicht KI für Studierende, die den Struggle umgeht
  • Verbindung zum Evaluationsparadox: Wenn Studierende Aufgaben nicht lösen können, gibt ihnen KI-Zugang die Illusion von Kompetenz ohne echtes Lernen

The Beach, Not the Ant

(Simon und Laird 2019)

  • Herbert Simons Einsicht: Verhalten wird von der Umgebung geformt, nicht von der Motivation
  • Die Ameise am Strand: Der komplexe Weg der Ameise spiegelt die Oberfläche wider, nicht die Ameise
  • Studierende verhalten sich rational in der gegebenen Umgebung
  • Vier Umgebungsfaktoren: Aufgabendesign, Prüfungsformat, KI-Zugänglichkeit, Strukturelle Anreize
  • Gestalte den Strand, nicht die Ameise

Gestalte den Strand, nicht die Ameise



Kognitive Arbeit als Produkt

Aufgaben gestalten, bei denen der Denkprozess das Ergebnis ist, nicht nur das Endprodukt.


Prozess bewerten

Den Weg zum Ergebnis prüfen, nicht nur das Ergebnis selbst.


Produktiven Struggle ermöglichen

Den Weg des eigenen Denkens zum Weg des geringsten Widerstands machen.


Der richtige KI-Einsatz: KI für Dozierende zum Redesign der Lernumgebung, nicht KI für Studierende zum Umgehen des Lernprozesses.

  • Kognitive Arbeit als Produkt: Nicht nur das Ergebnis zählt, sondern der Denkprozess
  • Prozess bewerten: Nicht nur was rauskommt, sondern wie
  • Produktiven Struggle ermöglichen: Eigenes Denken als Weg des geringsten Widerstands
  • KI für Dozierende: Aufgaben besser kalibrieren, gestufte Übungen erstellen
  • Nicht KI für Studierende, die den Lernprozess umgeht

Die Kernaussage


Das Evaluationsparadox:

Studierende können KI-Nutzung nicht selbst regulieren.

Ihnen fehlt die Kompetenz, um KI-Output zu bewerten.

Bounded Rationality:

Studierende werden KI-Nutzung nicht selbst regulieren.

Die Umgebung macht Outsourcing zum rationalen Weg.


Zusammen: Wir können uns nicht auf das Urteilsvermögen der Studierenden allein verlassen.


KI-Werkzeuge sind für Experten gemacht.

Fundamente zuerst aufbauen. Umgebungen gestalten, die Denken erfordern. Produktiven Struggle als natürlichen Weg ermöglichen.

  • Evaluationsparadox: Studierende KÖNNEN nicht selbst regulieren (fehlende Kompetenz)
  • Bounded Rationality: Studierende WERDEN nicht selbst regulieren (Umgebung ermöglicht Abkürzung)
  • Zusammen: Wir können uns nicht auf Studierende allein verlassen
  • KI-Werkzeuge sind für Experten gemacht (Feststellung, keine Wertung)
  • Konsequenz: Fundamente zuerst, Umgebungen gestalten, produktiven Struggle ermöglichen

Beginner: Was machen Sprachmodelle?

LLMs als Textvorhersage

Ein Sprachmodell sagt das nächste Wort vorher, basierend auf allem, was davor steht.


\[P(\text{Wort}_{i+1} \mid \text{Kontext}, \text{Modell})\]


Gegeben “Der Hund liegt auf dem”, berechnet das Modell:

  • “Boden” → 32%
  • “Sofa” → 24%
  • “Bett” → 18%
  • “Teppich” → 14%
  • …

Das Modell wählt ein Wort, hängt es an den Kontext an, und wiederholt den Prozess. So entsteht Text, Wort für Wort.


Zwei Faktoren bestimmen die Vorhersage:

  1. Kontext: Was wurde bisher gesagt?
  2. Modell: Was hat das System aus Trainingsdaten gelernt?


Für eine vertiefte Einführung: BFH Beginner-Kurs

Ein Sprachmodell wie ChatGPT funktioniert im Kern wie ein ausgefeilter Autocomplete-Mechanismus. Es sagt das nächste Wort vorher, basierend auf dem bisherigen Kontext und dem, was es aus Trainingsdaten gelernt hat. Dieser Prozess wiederholt sich Wort für Wort. Für eine vertiefte Einführung verweise ich auf den Beginner-Kurs. Was für unsere heutige Diskussion zählt, ist eine bestimmte Eigenschaft dieses Prozesses.

Die entscheidende Eigenschaft



LLMs produzieren Text, der flüssig, selbstbewusst und kohärent klingt.


Das Ergebnis liest sich wie ein Expertentext.

Aber Flüssigkeit ist nicht dasselbe wie Korrektheit.


Warum das für Lernen gefährlich ist, erklärt die Cognitive Load Theory.

Die entscheidende Eigenschaft von LLMs für unsere Diskussion: Sie produzieren Text, der flüssig, selbstbewusst und kohärent klingt. Das Ergebnis liest sich wie ein Expertentext, unabhängig davon, ob der Inhalt stimmt. Flüssigkeit ist nicht dasselbe wie Korrektheit. Intermediate: Cognitive Load Theory

Das Arbeitsgedächtnis als Nadelöhr

Alles Lernen muss durch einen Engpass: das Arbeitsgedächtnis.


Eigenschaft
Kapazität ~4 Elemente
Dauer 15-30 Sekunden
Verarbeitung 1 Element aktiv


Keine Technologie kann diesen Engpass umgehen. KI kann Information liefern, aber die aktive Verarbeitung muss im eigenen Kopf stattfinden.

Das Arbeitsgedächtnis ist der Flaschenhals, durch den alles Lernen hindurch muss. Es kann ungefähr vier Elemente gleichzeitig halten, und zwar für 15 bis 30 Sekunden. Nur ein Element wird aktiv verarbeitet. Die Grafik zeigt drei Szenarien. Schlechtes Design: Zu viel extrinsische Last, kein Raum für lernrelevante Verarbeitung. Gutes Design: Extrinsische Last minimiert, 60% der Kapazität für lernrelevante Verarbeitung. Outsourcing: Die lernrelevante Verarbeitung fällt fast komplett weg, weil die KI die Denkarbeit übernimmt. 55% der Kapazität bleiben ungenutzt. Die Arbeit findet nicht statt.

Drei Arten kognitiver Belastung

Die Cognitive Load Theory unterscheidet drei Arten von Belastung, die um dieselbe begrenzte Kapazität konkurrieren:


Extrinsische Last

Verursacht durch schlechtes Design

  • Unklare Aufgabenstellung
  • Inkonsistente Notation
  • Irrelevante Informationen

Trägt nichts zum Lernen bei. Minimieren.

Intrinsische Last

Verursacht durch das Material selbst

  • Abhängig von der Elementinteraktivität
  • Bestimmt durch das Vorwissen der Lernenden
  • Kann durch Scaffolding gesteuert werden

Nicht eliminierbar, aber steuerbar.

Lernrelevante Verarbeitung

Die produktive kognitive Arbeit

  • Schemabildung
  • Integration neuer Information
  • Automatisierung von Prozeduren

Das Ziel: maximieren.


Aufgabendesign = extrinsische Last senken, intrinsische Last steuern, lernrelevante Verarbeitung maximieren.

Die Cognitive Load Theory unterscheidet drei Arten von Belastung. Extrinsische Last wird durch schlechtes Design verursacht und trägt nichts zum Lernen bei. Intrinsische Last kommt vom Material selbst und hängt entscheidend vom Vorwissen ab. Lernrelevante Verarbeitung ist die produktive kognitive Arbeit, die Schemata aufbaut. Alle drei konkurrieren um dieselbe begrenzte Kapazität. Das Ziel von Aufgabendesign: extrinsische Last minimieren, intrinsische Last steuern, lernrelevante Verarbeitung maximieren.

Prinzip 1: Extrinsische Last minimieren

Extrinsische Last ist alles, was Arbeitsgedächtnis verbraucht, ohne zum Lernen beizutragen.


Typische Quellen in Mathe-Übungen

  • Unklare Aufgabenstellung: Was genau soll gelöst werden?
  • Inkonsistente Notation: Mal \(x\), mal \(X\), mal kursiv, mal nicht
  • Split Attention: Aufgabe auf Seite 3, Formelsammlung auf Seite 12
  • Redundanz: Dieselbe Information in Text und Grafik, leicht unterschiedlich formuliert

Gegenstrategien

  • Integriertes Format: Alle relevanten Informationen direkt bei der Aufgabe
  • Konsistente Notation: Ein Symbol, eine Bedeutung
  • Klare Aufgabenstruktur: Sofort erkennbar, was zu tun ist
  • Entfernen von Irrelevantem: Weniger ist mehr


Extrinsische Last zu senken kostet nichts und gibt Kapazität frei.

Das ist der einfachste Hebel im Aufgabendesign.

Extrinsische Last ist der einfachste Hebel, weil sie nichts zum Lernen beiträgt. In typischen Mathe-Übungen gibt es viele Quellen: unklare Aufgabenstellungen, inkonsistente Notation, Split Attention zwischen Aufgabe und Referenzmaterial. Die Gegenstrategien sind einfach: integriertes Format, konsistente Notation, klare Struktur. Das kostet nichts und gibt sofort Kapazität frei für lernrelevante Verarbeitung.

Prinzip 2: Vorwissen bestimmt das Aufgabendesign

Dieselbe Aufgabe hat unterschiedliche intrinsische Last für verschiedene Lernende.


Aufgabe: Löse \(-1(-x - 7) = 2x - 20\)


Für Anfänger:innen

Hohe Elementinteraktivität:

  • Was bedeutet das Minuszeichen vor der Klammer?
  • Wie verteile ich?
  • Wie bringe ich \(x\) auf eine Seite?
  • Welche Rechenregeln gelten?

Jedes Element muss einzeln im Arbeitsgedächtnis gehalten werden.



Für Fortgeschrittene

Niedrige Elementinteraktivität:

  • “Klammer auflösen” → ein Schema
  • “Terme zusammenfassen” → ein Schema
  • “Nach \(x\) auflösen” → ein Schema

Drei Schritte, drei Slots. Problemlos.


→ Dieselbe Aufgabe, aber verschiedene kognitive Kosten.

Hier wird es für das Aufgabendesign entscheidend. Dieselbe Gleichung hat völlig unterschiedliche kognitive Kosten für verschiedene Lernende. Für Anfänger:innen ist jedes Element einzeln zu verarbeiten: Was bedeutet das Minus, wie verteile ich, wie bringe ich x auf eine Seite. Für Fortgeschrittene sind das drei automatisierte Schritte, drei Schemata, drei Slots. Dieselbe Aufgabe, aber radikal verschiedene Anforderungen ans Arbeitsgedächtnis.

Der Expertise-Umkehr-Effekt

Was für Anfänger:innen hilft, schadet Fortgeschrittenen, und umgekehrt.

Ein Übungsblatt für alle ist per Definition für die meisten falsch.

Die Aufgabe muss zum Vorwissen passen, nicht umgekehrt.

Der Expertise-Umkehr-Effekt zeigt: Was für Anfänger:innen hilft, schadet Fortgeschrittenen. Worked Examples sind für Anfänger:innen hochwirksam, weil sie die intrinsische Last managen. Für Expert:innen sind sie redundant und erzeugen unnötige extrinsische Last. Umgekehrt ist Problemlösen für Expert:innen effektiv, aber für Anfänger:innen überfordernd. Die Konsequenz: Ein Übungsblatt für alle ist per Definition für die meisten falsch. Die Aufgabe muss zum Vorwissen passen.

Prinzip 3: Scaffolding steuert die intrinsische Last

Wenn die intrinsische Last zu hoch ist, brauchen Lernende Gerüste, nicht einfach mehr Zeit.


Vom Beispiel zum Problem (Fading)

Schritt Format
1 Worked Example: Vollständig durchgearbeitetes Beispiel
2 Completion Problem: Teilweise gelöst, Lücken füllen
3 Hinweis-gestützt: Nur strategische Hinweise
4 Eigenständig: Ohne Unterstützung


Jede Stufe reduziert die Unterstützung und erhöht die kognitive Eigenleistung.

Beispiel: Gleichung lösen

Stufe 1 (Worked Example):

\(-1(-x - 7) = 2x - 20\)

Schritt 1: Klammer auflösen → \(x + 7 = 2x - 20\)

Schritt 2: \(x\) isolieren → \(7 + 20 = 2x - x\)

Schritt 3: Vereinfachen → \(27 = x\)


Stufe 2 (Completion):

\(-1(-x - 7) = 2x - 20\)

Schritt 1: Klammer auflösen → \(\underline{\quad\quad\quad\quad}\)

Schritt 2: \(x\) isolieren → \(7 + 20 = 2x - x\)

Schritt 3: Vereinfachen → \(27 = x\)

Scaffolding ist das dritte Prinzip. Wenn die intrinsische Last zu hoch ist, brauchen Lernende Gerüste. Die effektivste Strategie ist Fading: Man beginnt mit vollständig durchgearbeiteten Beispielen, geht dann zu Completion Problems über, wo Teile fehlen, dann zu Hinweisen, und schliesslich zu eigenständigem Lösen. Bei unserem Gleichungsbeispiel: Stufe 1 zeigt die vollständige Lösung, Stufe 2 lässt den ersten Schritt offen. Die kognitive Eigenleistung steigt graduell.

Was passiert, wenn Studierende ChatGPT benutzen?

ChatGPT liefert die Lösung. Aber nicht das Scaffolding.


ChatGPT-Antwort

“Löse \(-1(-x - 7) = 2x - 20\)”

→ Sofort die vollständige Lösung, korrekt formatiert, flüssig formuliert.

  • Keine Diagnose des Vorwissens
  • Keine angepasste Unterstützung
  • Keine Lücken zum Selbstdenken
  • Kein Fading

Das Produkt sieht aus wie ein Worked Example, ist aber keines.

Der Unterschied

Ein Worked Example ist pädagogisch gestaltet:

  • Schritte sind so gewählt, dass Schemata aufgebaut werden
  • Die Struktur lädt zur Selbsterklärung ein
  • Es ist Teil einer Fading-Sequenz

ChatGPT-Output ist optimiert für Korrektheit und Flüssigkeit, nicht für Schemabildung.

Wer die Lösung liest, ohne selbst zu verarbeiten, baut keine Schemata auf.


Flüssiger Output erzeugt die Illusion des Verstehens. Die Lernenden merken nicht, dass die kognitive Arbeit fehlt.

Hier treffen die LLM-Eigenschaft aus dem Beginner-Teil und die CLT-Prinzipien aufeinander. Wenn Studierende ChatGPT die Gleichung lösen lassen, bekommen sie eine korrekte, flüssig formulierte Lösung. Das sieht aus wie ein Worked Example, ist aber keines. Ein echtes Worked Example ist pädagogisch gestaltet: Die Schritte sind so gewählt, dass Schemata aufgebaut werden, und es ist Teil einer Fading-Sequenz. ChatGPT-Output ist für Korrektheit und Flüssigkeit optimiert, nicht für Schemabildung. Und weil der Output flüssig ist, entsteht die Illusion des Verstehens. Die Lernenden merken nicht, dass die kognitive Arbeit fehlt.

Das Evaluationsparadox



Um KI-Output zu beurteilen,

braucht man die Schemata,

die die Aufgabe aufbauen sollte.


Ohne eigene Schemata gibt es kein internes Referenzsignal.

Flüssiger KI-Output unterdrückt den Zweifel.

Das ist keine Frage der Motivation. Das ist kognitive Architektur.

Das Evaluationsparadox schliesst den Kreis. Um zu beurteilen, ob ein KI-Output korrekt ist, braucht man genau die Schemata, die die Aufgabe aufbauen sollte. Ohne eigene Schemata gibt es kein internes Referenzsignal. Und weil der Output flüssig ist, wird der Zweifel unterdrückt. Das ist keine Frage der Motivation. Das ist kognitive Architektur. CLT erklärt, warum das passiert, und zeigt auch den Weg hinaus.

Advanced: KI-Tools nach CLT-Prinzipien

Die Designfrage



Wenn unstrukturierte ChatGPT-Nutzung das Problem ist:


Wie sähe ein KI-Tool aus, das CLT-Prinzipien umsetzt?


Antwort: Ein Tool, das zuerst diagnostiziert und dann angepasst scaffoldet.

Jetzt die Frage aus dem Advanced-Kurs: Wenn unstrukturierte ChatGPT-Nutzung das Problem ist, wie sähe ein KI-Tool aus, das CLT-Prinzipien umsetzt? Die Antwort: Ein Tool, das zuerst diagnostiziert, wo die Lernenden stehen, und dann die Unterstützung anpasst. Nicht eine Lösung für alle, sondern das richtige Scaffolding für das richtige Vorwissen.

Beispiel: Gleichungen lösen

Aufgabe: \(-1(-x - 7) = 2x - 20\)

Diese Aufgabe erfordert drei Teilkompetenzen:


Schritt 1

Distribuieren

\(-1 \cdot (-x) = x\)

\(-1 \cdot (-7) = 7\)

→ \(x + 7 = 2x - 20\)

Schritt 2

Terme zusammenfassen

\(7 + 20 = 2x - x\)

→ \(27 = x\)

Schritt 3

Variable isolieren

\(x = 27\)

Prüfung: \(-1(-27-7) = 2(27)-20\)

\(34 = 34\) ✓


Ein CLT-informiertes Tool fragt: Welche dieser Teilkompetenzen beherrscht die Person bereits?

Nehmen wir ein konkretes Beispiel: die Gleichung -1(-x - 7) = 2x - 20. Sie erfordert drei Teilkompetenzen: Distribuieren, Terme zusammenfassen, Variable isolieren. Ein CLT-informiertes Tool fragt nicht einfach “Löse die Gleichung”, sondern diagnostiziert zuerst: Welche dieser Teilkompetenzen beherrscht die Person bereits? Je nach Antwort wird unterschiedlich scaffoldet.

Diagnostik und Scaffolding

Das Tool passt die Unterstützung an das diagnostizierte Vorwissen an:


flowchart = {
  const w = 900;
  const h = 520;

  const svg = d3.create("svg")
    .attr("viewBox", [0, 0, w, h])
    .attr("width", w)
    .attr("height", h)
    .style("background", "transparent")
    .style("font-family", "system-ui, sans-serif");

  // Helper functions
  function roundRect(g, x, y, width, height, fill, stroke, text, fontSize) {
    g.append("rect")
      .attr("x", x).attr("y", y)
      .attr("width", width).attr("height", height)
      .attr("rx", 8).attr("fill", fill)
      .attr("stroke", stroke).attr("stroke-width", 1.5);
    const lines = text.split("\n");
    for (let i = 0; i < lines.length; i++) {
      g.append("text")
        .attr("x", x + width/2).attr("y", y + height/2 + (i - (lines.length-1)/2) * 18)
        .attr("text-anchor", "middle").attr("dominant-baseline", "middle")
        .attr("fill", "#1A1714").attr("font-size", fontSize || "13px")
        .text(lines[i]);
    }
  }

  function diamond(g, cx, cy, rx, ry, fill, stroke, text) {
    const points = `${cx},${cy-ry} ${cx+rx},${cy} ${cx},${cy+ry} ${cx-rx},${cy}`;
    g.append("polygon")
      .attr("points", points)
      .attr("fill", fill).attr("stroke", stroke).attr("stroke-width", 1.5);
    const lines = text.split("\n");
    for (let i = 0; i < lines.length; i++) {
      g.append("text")
        .attr("x", cx).attr("y", cy + (i - (lines.length-1)/2) * 16)
        .attr("text-anchor", "middle").attr("dominant-baseline", "middle")
        .attr("fill", "#1A1714").attr("font-size", "12px")
        .text(lines[i]);
    }
  }

  function arrow(g, x1, y1, x2, y2, label, labelSide) {
    g.append("line")
      .attr("x1", x1).attr("y1", y1).attr("x2", x2).attr("y2", y2)
      .attr("stroke", "#64748b").attr("stroke-width", 1.5)
      .attr("marker-end", "url(#arrowhead)");
    if (label) {
      const mx = (x1 + x2) / 2;
      const my = (y1 + y2) / 2;
      const dx = labelSide === "left" ? -20 : (labelSide === "right" ? 20 : 0);
      g.append("text")
        .attr("x", mx + dx).attr("y", my - 6)
        .attr("text-anchor", "middle").attr("fill", "#64748b")
        .attr("font-size", "11px").attr("font-weight", "600")
        .text(label);
    }
  }

  // Arrowhead marker
  svg.append("defs").append("marker")
    .attr("id", "arrowhead").attr("viewBox", "0 0 10 7")
    .attr("refX", 10).attr("refY", 3.5)
    .attr("markerWidth", 8).attr("markerHeight", 6)
    .attr("orient", "auto")
    .append("polygon").attr("points", "0 0, 10 3.5, 0 7").attr("fill", "#64748b");

  const g = svg.append("g");

  // Start
  roundRect(g, 350, 10, 200, 40, "#0072B2", "#0072B2", "Aufgabe präsentieren", "14px");
  g.select("rect").attr("fill", "#0072B2");
  g.selectAll("text").filter((d,i) => i === 0).attr("fill", "white").attr("font-weight", "bold");

  // Diagnostic question 1
  diamond(g, 450, 110, 160, 50, "rgba(0, 114, 178, 0.1)", "#0072B2", "Kannst du\n-1(-x-7) auflösen?");

  arrow(g, 450, 50, 450, 60, null);

  // Left: can't distribute
  roundRect(g, 30, 170, 220, 55, "rgba(213, 94, 0, 0.08)", "#D55E00", "Worked Example:\nDistribuieren Schritt für Schritt");
  arrow(g, 290, 110, 140, 170, "Nein", "left");

  // Right: can distribute
  diamond(g, 700, 200, 160, 50, "rgba(0, 114, 178, 0.1)", "#0072B2", "Kannst du Terme\nzusammenfassen?");
  arrow(g, 610, 110, 700, 150, "Ja", "right");

  // From worked example back
  roundRect(g, 30, 260, 220, 40, "rgba(100, 116, 139, 0.08)", "#64748b", "Erneut versuchen");
  arrow(g, 140, 225, 140, 260, null);
  // Arrow from retry back up
  g.append("path")
    .attr("d", "M 250,280 Q 320,280 350,200 Q 380,120 450,60")
    .attr("fill", "none").attr("stroke", "#64748b")
    .attr("stroke-width", 1).attr("stroke-dasharray", "4,3");

  // Can't combine terms
  roundRect(g, 500, 290, 220, 55, "rgba(213, 94, 0, 0.08)", "#D55E00", "Completion Problem:\nx + 7 = 2x - 20 → ___ = x");
  arrow(g, 620, 250, 610, 290, "Nein", "left");

  // Can combine terms
  roundRect(g, 750, 290, 180, 55, "#rgba(0, 114, 178, 0.08)", "#0072B2", "Nur Hinweis:\n«Fasse die Terme zusammen»");
  arrow(g, 780, 250, 840, 290, "Ja", "right");

  // Final
  roundRect(g, 350, 430, 200, 50, "rgba(0, 114, 178, 0.15)", "#0072B2", "Eigenständig lösen\n(Fading complete)");
  arrow(g, 610, 345, 520, 430, null);
  arrow(g, 840, 345, 520, 430, null);

  // Legend

Es beginnt mit der Aufgabe und stellt dann diagnostische Fragen. “Kannst du die Klammer auflösen?” Wenn nein, gibt es ein Worked Example für genau diesen Schritt, dann einen erneuten Versuch. Wenn ja, geht es weiter zur nächsten Teilkompetenz. Je nach Ergebnis gibt es entweder ein Completion Problem oder nur einen Hinweis. Am Ende steht eigenständiges Lösen. Das Tool implementiert alle drei CLT-Prinzipien: Diagnostische Fragen für Prinzip 2, angepasstes Scaffolding für Prinzip 3, und eine klare, fokussierte Struktur für Prinzip 1.

Designentscheidung CLT-Prinzip Wirkung
Diagnostische Fragen zu Beginn Vorwissen einschätzen (Prinzip 2) Scaffolding passt zum aktuellen Stand
Worked Examples bei Wissenslücken Intrinsische Last steuern (Prinzip 3) Überforderte Lernende werden unterstützt
Fading: schrittweiser Abbau der Hilfe Intrinsische Last steuern (Prinzip 3) Kognitive Eigenleistung steigt graduell

Der Unterschied zu ChatGPT: Wer macht die kognitive Arbeit?

ChatGPT übernimmt die Arbeit. Ein CLT-Tool verteilt sie.

Diese Tabelle zeigt, wie jede Designentscheidung im Tool auf ein CLT-Prinzip zurückgeht. Diagnostische Fragen passen das Scaffolding ans Vorwissen an. Worked Examples steuern die intrinsische Last. Fading steigert die Eigenleistung graduell. Klare Aufgaben minimieren extrinsische Last. Und das Tool löst nie vollständig für den Lernenden. Der entscheidende Kontrast: ChatGPT übernimmt die kognitive Arbeit. Ein CLT-informiertes Tool verteilt sie so, dass Schemata aufgebaut werden.

Zusammenfassung

Drei Erkenntnisse


1. Extrinsische Last minimieren ist der einfachste Hebel. Klare Aufgaben, konsistente Notation, integriertes Format.


2. Vorwissen bestimmt das Aufgabendesign. Ein Übungsblatt für alle ist für die meisten falsch. Diagnostik ist der Schlüssel.


3. KI kann CLT-Prinzipien umsetzen, aber nur wenn sie dafür gebaut wird. ChatGPT ist kein Lerntool. Ein CLT-informiertes Tool kann eines sein.

Drei Erkenntnisse zum Mitnehmen. Erstens: Extrinsische Last minimieren ist der einfachste Hebel und kostet nichts. Zweitens: Vorwissen bestimmt, wie die Aufgabe aussehen muss. Ein Übungsblatt für alle ist für die meisten falsch. Drittens: KI kann CLT-Prinzipien umsetzen, aber nur wenn sie dafür designt wird. Unstrukturiertes ChatGPT ist kein Lerntool. Ein CLT-informiertes Tool kann eines sein.
